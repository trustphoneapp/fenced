# B05 clean-room enforcement

B05.1 classifies the complete local namespace through one closed policy. It is a local-development exclusion result, not clean-room certification, originality proof, no-private-history claim, or public-release approval.

The classifier allows only governed source, registered persistent generated artifacts, B03-derived ephemeral outputs, exact opaque local-only roots, and four exact legacy local-boundary records: `AGENTS.md`, `docs/implementation/evidence-ledger.md`, `docs/implementation/goal.md`, and `docs/implementation/task-manifest.yaml`. Each required legacy record must be present as a canonical regular single-link file. Their verified presence derives the legacy public-release block; it is not a caller assertion.

Paths, policy arrays, generated-record fields, every top-level path kind and presence rule, the exact B03 policy bytes/hash/output namespaces/node-module exclusions, and every numeric limit are closed exact values. Traversal rejects links, hard links, special files, undeclared opaque directories, nested Git markers, noncanonical roots, portable-name collisions and aliases, path-limit overflow, generated-directory or banner laundering, executables, embedded container/polyglot signatures, binary formats, malformed UTF-8, and disallowed control bytes. Generated-directory components use exact closed families after ASCII case folding and removal of only dot, hyphen, and underscore separators; ordinary components that merely share a substring are not denied, and only exact B03 ephemeral namespaces or registered persistent paths bypass the denial. Container recognition is structural: TAR requires a checksum-valid complete block header; ar requires its offset-zero global header plus either the documented zero-member form or a bounded member header/trailer/size; newc/CRC cpio requires an offset-zero fixed hexadecimal header with bounded aligned name/data and CRC validation where applicable; PDF permits a leading header within 1,024 bytes only when object syntax and an end marker corroborate it. Bare or interior prose markers are not archive evidence. The closed lexical marker grammar examines the complete decoded body of every accepted text file up to the exact 1,048,576-byte read limit; larger files fail explicitly instead of leaving an unscanned tail. A monotonic per-line cursor tokenizes only ASCII-indented, line-leading `//`, `#`, `;`, and `--` comment runs of one unchanged family and line-leading `<!-- ... -->` or `/* ... */` spans. On the first and each continued C-comment segment, ASCII indentation followed by a conventional decorative star run and optional adjacent bang—or the bang form used by documentation comments—is removed before classification; a decorative star run immediately before the block terminator is also removed. Each such run is bounded to 64 and overflow fails closed. Decoration removal is confined to these comment edges and does not remove punctuation later inside the semantic text. After each HTML or C terminator, the unconsumed physical-line remainder is tokenized again, allowing bounded adjacent or mixed comment tokens without treating ordinary code as a comment. Each run or span is bounded to 65,536 comment-body bytes and 256 logical lines, and each file is bounded to 4,096 recognized comment tokens; exceeding a bound fails closed. ASCII case is folded, and dot, underscore, or hyphen insertion is permitted only between letters of a recognized keyword. Phrase tokens must retain at least one actual ASCII whitespace, dot, underscore, or hyphen separator; separators are never globally deleted before boundary decisions. The bounded `by` attribution token must end exactly, so separated tool names qualify while longer words beginning with those letters do not. One canonical declaration-stem table defines standalone and attributed producer forms, machine/automatic/code forms, exact subject-copula forms, directives, and prohibition heads. Unterminated partial-prefix matchers are generated from the same declaration stems, including partial code-origin forms, rather than from a separate word list. Editing prohibitions qualify only when followed by one of those explicit generated-origin targets or a directive; unrelated machine settings, learning examples, automation settings, and ordinary prose remain outside the rule. Folding of line breaks occurs only inside one comment run or span and never crosses executable text, a noncomment line, or a different comment family. Exact registered generated files are exempt, while matches elsewhere fail `GENERATED_UNDOCUMENTED`; ordinary noun claims about reports or users, active-voice runtime claims, comparisons, and ordinary semantic prose remain outside this anchored origin-banner grammar. This lexical control is not semantic proof of every possible code-generation origin. Reads use Node's local no-follow file-descriptor API, are size-bounded, and compare descriptor identity before and after reading. This is a local adapter control, not proof against a hostile process with equivalent host authority.

A synthetic private-boundary test marker is accepted only inside one of the four exact legacy records. The same marker in any other file is rejected with a content-free rule code. The marker is test evidence only and neither identifies nor reads any private system.

The classifier delegates manifest, dependency, source-security, SBOM, secret, and network checks to their existing B03 stages. Its production PASS authority is only the fixed reviewed Node entrypoint invoked by `scripts/safe-verify.mjs` through the exact `sanitizeEnvironment` allow set and path relationships; the one macOS-injected text-encoding key is accepted only in its fixed numeric form. Ambient `NODE_OPTIONS`, `NODE_PATH`, credentials, cloud/proxy variables, user configuration, and every other extra key fail after the checker entrypoint. Node may execute a preload before the first checker instruction, so the checker cannot suppress, redact, or make claims about pre-entrypoint output or behavior; it guarantees only that, once entered with a forbidden ambient key still present, it emits no PASS, returns nonzero, and limits checker-owned diagnostics to one content-free line. The environment shape is a reviewed invocation contract, not cryptographic caller attestation or protection from a hostile same-user process. Successful production output is explicitly `SAFE_VERIFY_BOUND`; standalone API results remain local test evidence. `public-ready` remains fail-closed pending legacy-boundary removal, opaque local state removal, provenance reconciliation, V01, V06, and HG-6.

B05.2 binds this classifier to trust baseline `zintus-continuity-local-trust@5`, tool-payload inventory `zintus-continuity-tool-payloads@3`, and unsigned provenance predicate `zintus-continuity.local-unsigned-provenance@14`. The classifier's one governed-file discovery result excludes only exact opaque local roots, exact B03 ephemeral outputs, and the current B05 provenance envelope itself. The B03 subject list and generated B05 artifact entries must equal that strict UTF-8 ordered universe in both directions. B03 R12 and B04 R1-R5 remain immutable history and are never writable generator targets. The B05 R1 envelope is unsigned, has only pending detached external-review slots, and cannot establish acceptance, public readiness, or completion.
